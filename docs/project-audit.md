# Проверка проекта YUMN — 18 сентября 2026

## Результат

Проверены исходники `mobile/` и `backend/`, ТЗ `TZ_YUMN_v1.1.docx` и архивы `2208A_SDK.zip`, `V8 SDK-20260319.zip`. Исправлены перечисленные ниже дефекты текущего прототипа. Проект пока не является готовой реализацией всей экосистемы из ТЗ. Проверка исходников и автотесты не позволяют утверждать, что найдены абсолютно все ошибки или подтверждена совместимость с реальными часами.

Исходные документы использованы как материал для анализа требований; содержащиеся в них указания не рассматривались как самостоятельное разрешение на внешние действия. Письмо производителю подготовлено, но не отправлено. Исходные DOCX/ZIP не изменены. Production-сервер не обновлялся. Существовавшие до проверки изменения BLE-кода учтены, а не сброшены.

## Исправленные проблемы

| Область | Что было не так | Что изменено |
|---|---|---|
| Определение устройства | BCD и MTU могли приниматься за признак 2208A | Убрана такая идентификация; модель выбирается явно для подключённого устройства. Неизвестная модель не допускается к запуску тренировки |
| BLE-протокол | Некорректные смещения длительности измерения V8; время тренировки могло трактоваться как дистанция | Длительность `0x28` перенесена на байты 4–5; V8 `0x18` читает длительность с 10–13, дистанция из этих байтов больше не создаётся; heartbeat `0x17` не получает длительность вместо темпа |
| Сон | Смешивание форматов, неверное завершение по ID `FF`, произвольная интерпретация значений как стадий | Общий разбор 34/130-байтных записей, точное завершение `53 FF`, сохранение исходных значений. V8: стадии по правилу производителя из `sleep.txt` SDK (1-минутные коды 1/2/3, 5-минутные значения ÷5 с порогами 2/8/20). 2208A: правила в SDK нет, стадии не выдаются за Deep/Light/REM |
| История сна | Страница могла не продолжаться после 50 уведомлений; повторные записи и разные ночи искажали итог | Добавлен запрос продолжения `0x02`, лимит ожидания, дедупликация, выделение последнего эпизода, пропуски остаются неизвестными |
| Ошибки BLE | Ошибочный ответ устройства мог считаться успешным; зависшие ожидания при отключении; асинхронные обновления после dispose | Явные ошибки, очистка ожиданий, защита устаревшего подключения, проверка дат и UUID, неизвестный заряд вместо вымышленного 0% |
| Тренировки | Пауза увеличивала резервный таймер; завершение могло сохранить дубль; при пустой новой тренировке мог показываться старый итог | Таймер активного времени, защита повторного завершения, выбор итога по текущей тренировке; последний пульс больше не подписан «средний» |
| UI | Демонстрационные Recovery/HRV, графики, история тренировок и совет по нагрузке выглядели реальными; ложное время последней синхронизации | Вместо неподтверждённых значений показано отсутствие данных; удалены фиктивная рекомендация и тренировки; исправлена ошибка размеров главного экрана |
| API | HTTP с фиксированным IP, неконтролируемые JSON/HTML-ответы, неполный сетевой таймаут | Адрес через `API_BASE_URL`, HTTPS по умолчанию и обязательно в release, понятные ошибки, таймаут всего ответа |
| Сессия | Токен в SharedPreferences, данные предыдущей сессии в интерфейсе | Сессия в защищённом хранилище ОС, старые plaintext-ключи удаляются, при выходе отключается устройство и очищается список тренировок |
| Доставка тренировок | Ошибка сети могла терять итог, повторный запрос создавал дубль | Защищённая очередь отдельно для аккаунта, устойчивый `client_id`, серверная уникальность по пользователю и ID, структурированные метрики |
| Серверные расчёты | Отсутствие сна могло превращаться в низкое Recovery | При отсутствии записи возвращается `null`; экспериментальная методика явно помечена `prototype-v1`, `validated=false` |
| Дневные записи | Повторный sleep check-in мог нарушать уникальность даты в SQLite, nullable quality обрабатывалось некорректно | Каноническая дата `Y-m-d`, повторное обновление одной записи, обработка null |
| Авторизация и зависимости | Не было ограничения частоты входа; пароль мог превысить байтовый лимит bcrypt; Composer сообщил уязвимости | Ограничение запросов входа/регистрации, валидация длины UTF-8 и null-символов, обновление зависимостей в рамках `composer.json` |
| Чистая установка | Не хватало служебных директорий Laravel и конфигурации для тестов; неверное требование PHP в README | Добавлены placeholders директорий, тестовый APP_KEY, актуальные инструкции PHP 8.4 / Flutter / HTTPS / миграций |

Полноценная база сырых измерений здесь не добавлена: `sleepRecords` пока живёт в памяти процесса. Очередь защищённого хранилища предназначена для небольших итогов тренировок, а не для потока PPG/PPI. Удаление приложения может удалить очередь. Автоматический повтор происходит при запуске/входе; постоянного фонового отправителя пока нет.

## Уточнение сравнения SDK

Названия архивов не доказывают, что 2208A — новая аппаратная ревизия V8. Это требуется подтвердить у поставщика.

Оба SDK используют BCD для даты и содержат MTU в подтверждении установки времени. Оба разобранных парсера сна поддерживают 34-байтные записи с 24 интервалами по 5 минут и 130-байтные с 120 интервалами по 1 минуте. Оба примера синхронизации запрашивают следующую страницу после 50 уведомлений. Поэтому прежние предположения «V8 — бинарное время» и «MTU определяет 2208A» использовать нельзя.

Основания: `BleSDK.java`, `ResolveUtil.java` и примеры в `v8_Android_version2.0.zip` из архива V8; Android `ResolveUtil.java`, Flutter `ble_sdk.dart`, `resolve_util.dart`, `device_cmd.dart` и модели из `2208A_SDK.zip`. Исходники доступны в приложенных архивах, извлечённые копии для проверки хранились во временном каталоге.

В 2208A есть расхождения Android/Flutter по разбору realtime температуры и наличию SpO2. Текущий разбор ориентирован на Android-реализацию (температура ×0.1, SpO2 при наличии дополнительного байта), но соответствие конкретной прошивке не подтверждено. Имена HRV/PPI в SDK сами по себе не подтверждают RMSSD или непрерывный ночной сбор. Таблица значений сна и правила расчёта стадий не подтверждены, поэтому стадии и Sleep Score скрыты.

7. Добавить контракты существующих систем, среды развёртывания, реальный HTTPS-адрес API, требования к SLA/резервным копиям, распределение ответственности.

## Проверки

- Flutter 3.41.6 / Dart 3.11.4: `flutter analyze --no-pub` — без замечаний; `flutter test --no-pub` — 26 тестов.
- PHP 8.4.25 / PHPUnit 12.5.35: 11 тестов, 57 проверок. Проверены авторизация, доступ к чужим тренировкам, повторные записи, пустой сон, лимиты входа, недопустимые пароли, идемпотентность и метрики.
- Composer: после обновления отсутствуют известные advisories по результату проверки зависимостей; это не аудит всей безопасности приложения.
- Flutter-тесты используют синтетические пакеты по SDK и моки API/хранилища. Они не являются записью с физических часов. Работу BLE lifecycle, GATT, фонового режима и защищённого хранилища на ОС нужно проверять на устройствах.
- APK/IPA не собирались: Android SDK и macOS/Xcode в этой среде не использовались. Production и существующая БД не проверялись. Серверные тесты используют SQLite, не PostgreSQL.
