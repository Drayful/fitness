# YUMN — Flutter + Laravel

В репозитории находятся мобильный прототип и API. Полная экосистема из ТЗ ещё не реализована. Текущий статус, исправления и ограничения: [аудит проекта](docs/project-audit.md). [Вопросы производителю](docs/manufacturer-questions.md).

Размещение Laravel рядом с существующим сайтом и подключение регистрации мобильного приложения описаны в [инструкции для сервера](docs/server-registration-setup.md). Она рассчитана на `/var/www/ella_mobile` и публичный IP `80.242.213.87`, без нового домена.

- `backend/`: Laravel API, авторизация, тренировки, показания пульса, снимки SpO₂/температуры/шагов, наблюдения сна и экспериментальные расчёты.
- `mobile/`: Flutter, BLE-интеграция с семействами SDK V8/2208A и отправка измерений и итогов тренировок.

## Локальный запуск

### Backend

Требования: PHP 8.4+, Composer, драйвер выбранной БД. `.env.example` настроен на PostgreSQL: укажите собственные реквизиты и создайте БД перед миграциями.

```powershell
cd backend
composer install
Copy-Item .env.example .env
# Настройте DB_* в .env.
php artisan key:generate
php artisan migrate
php artisan serve
```

`Copy-Item` и `key:generate` нужны только при первой настройке. Для существующего окружения сохраняйте `.env` и APP_KEY.

### Mobile

Проверено на Flutter 3.41.6 / Dart 3.11.4. Android minimum SDK 23. Для iOS требуется macOS/Xcode, provisioning и проверка Keychain Sharing (Runner.entitlements подключён к конфигурациям Runner).

```powershell
cd mobile
flutter pub get
flutter run --dart-define=API_BASE_URL=https://80.242.213.87
```

Этот IP уже задан в мобильном коде по умолчанию; `--dart-define` позволяет его переопределить. Суффикс `/api` не добавляйте. В release разрешён только HTTPS. Сертификат на IP и серверный маршрут должны быть настроены по инструкции выше.

Для Android-эмулятора и локального Laravel разрешите HTTP только в debug:

```powershell
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000 --dart-define=ALLOW_INSECURE_API=true
```

Этот debug-адрес относится к Android-эмулятору. На телефоне нужен доступный HTTPS-сервер. Для локального HTTP на iOS понадобятся отдельные debug-настройки ATS; production-исключение для прежнего HTTP IP удалено.

После обновления потребуется повторный вход: старый токен из SharedPreferences удаляется; новая сессия хранится в защищённом хранилище ОС. Непереданные итоги тренировок и измерения сохраняются там отдельно для каждого аккаунта; повторная отправка выполняется при входе/запуске, возвращении приложения из фона и ручном обновлении экрана «Тренды». Экран показывает число записей, ожидающих отправки, и кнопку повтора. Это очередь небольших итоговых записей, а не полноценная локальная БД или гарантия непрерывного сбора в фоне. Выбранный язык интерфейса сохраняется на телефоне.

Во время активного подключения браслета приложение сохраняет снимок доступных показаний (пульс, SpO₂, температура, шаги) не чаще раза в 30 секунд. На главном экране отображается серверное среднее последних 10 сохранённых показаний пульса; на экране «Тренды» — последние 50 сохранённых снимков и недавние записи сна/тренировок. История тренировок загружается с сервера после входа; при наличии показаний сохраняется средний и максимальный пульс за тренировку. Наблюдаемый интервал сна и исходные значения стадий сохраняются даже при неизвестной расшифровке; время сна и Sleep Score в этом случае не вычисляются.

При поиске приложение сначала показывает ранее выбранные часы, устройства с рекламируемым BLE-сервисом FFF0 и устройства с похожими на V8/2208A именами. Остальные BLE-устройства доступны отдельно: часть часов не передаёт имя или сервис до подключения. Это подсказки, а не автоматическое определение модели; совместимость проверяется при подключении по GATT-сервису. При первом подключении каждых часов выберите подтверждённое семейство SDK на экране подключения. До выбора приложение не запускает поток измерений и не записывает показания с предположением о модели. При смене выбора поток останавливается и запускается заново для выбранного протокола. Приложение запоминает выбор отдельно для каждого устройства и применяет его при следующих подключениях, включая переключение между V8 и 2208A. Неизвестной модели нельзя запускать тренировку до подтверждения. Для безопасного распознавания новых устройств без первого выбора нужен документированный идентификатор модели от производителя.

## Обновление существующего сервера

Установите зависимости из `backend/composer.lock`, выполните миграции после резервного копирования и обновите конфигурационный кэш. Миграция `2026_09_27_000001_create_vital_snapshots_and_sleep_records` добавляет `vital_snapshots` и поле `records` в `sleep_observations`. Сначала обновляется сервер, затем мобильный клиент: новая сборка вызывает API-маршруты `/api/measurements/vitals` и `/api/measurements/vitals/recent`.

```powershell
cd backend
composer install --no-dev --optimize-autoloader
php artisan migrate --force
php artisan config:cache
sudo systemctl restart fitness-api.service
```

Параметры БД, HTTPS и секреты остаются только в серверном `.env`. Не запускайте `migrate:fresh`: он удалит данные. Перед обновлением сделайте резервную копию БД.

```powershell
cd backend
composer validate --no-check-publish
composer audit
php artisan test
```

```powershell
cd mobile
flutter analyze
flutter test
```

Автотесты не подтверждают работу конкретной прошивки, фоновую BLE-связь или физиологическую точность. Проверка на физических V8/2208A и сборки Android/iOS остаются обязательными перед выпуском.
